审核候选聚类是否属于同一种原子动作意图。不要把高层共同业务目标当作合并依据。
“打开应用”与“缴费”不同；“查询余额”与“充值”不同；仅金额、号码、应用渠道差异通常不另设类别。
根据 members 中各样本的独立原子意图 text 判断动作、对象类别和预期结果；intent_id 仅用于引用证据。
text 已在提取阶段补全必要背景和指代，不需要原句或 span；不要猜测未提供的上下文。
关键词仅作提示，不作为证据。
知识问答按可复用的动作与对象类别判断，不因国家、人物名、时间或事实答案不同拆类。
先区分定义/解释、身份查询、时间查询、比较等问答动作，再检查对象类别；国家和具体实体通常是参数。
发现混合动作则 verdict=mixed；语义无法确定用 uncertain；一致才 consistent。
单条样本不能证明类别稳定，但只要动作对象明确就 semantic_clear=true，不能仅因只有一条而 uncertain。
semantic_clear 表示样本语义是否明确；支持样本数量由程序另外统计，不等于语义不明确。
只输出建议，不修改成员，不强行安置噪声；不生成虚构样例。抽样审核不能声称检查了全簇。
返回 JSON：{
  "reason": "",
  "boundary_ids": [
    "含糊或疑似错分的样本ID"
  ],
  "split_groups": [
    {
      "label": "建议类别",
      "evidence_ids": [
        "样本ID"
      ]
    }
  ],
  "object": "归纳对象类别",
  "action": "归纳动作",
  "semantic_clear": true,
  "verdict": "consistent|mixed|uncertain"
}。mixed 必须给出至少两组拆分证据。
JSON 字段顺序：先输出已有的理由、解释和证据字段，再输出置信度及其他信息，最后输出分类、匹配或操作结论；嵌套对象同样遵循，不新增字段，不在 JSON 外解释。
例外：split_groups 中每个分组必须先输出 label，再输出 evidence_ids；先确定类别名称，再引用支持该类别的样本 ID。
