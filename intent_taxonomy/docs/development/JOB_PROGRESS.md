# 任务进度

在「运行任务」页面查看整体进度、当前轮次与阶段、已用时和实时日志。启动任务后自动选中该任务；刷新页面后会重新连接正在运行的任务，也可以点击历史任务查看结果。

## 两层进度

- **整体进度**：按照实际执行计划中的阶段估算。原子意图分析、向量计算、聚类、簇审核、边界复核、逐层命名审核、各轮叶子匹配及重聚类、最终验证和报告保存分别计为阶段。各阶段权重相同，所以百分比不代表已经消耗的时间比例，也不能推算剩余时间。
- **当前阶段**：分类、Skill 路由、逐 Task 审核提供实际处理数量。其他阶段显示当前执行状态，不编造条数。分类计数包括已复用的缓存和已结束的失败请求；失败数单独展示，不代表这些行已成功分类。

例如：`第 2 / 3 轮 · 语义分类与任务匹配 · 320 / 1000 条`。分类达到 100% 后，任务仍然要完成路由、审核和收敛等后续阶段。

## 完成、跳过与异常

- 关闭的功能不会进入执行计划。
- Dry Review 或提前收敛时，未执行轮次会标为「跳过」，并从剩余阶段的分母中排除。
- 自动收敛的 Global Check 未通过时，可选 Apply 阶段标为「跳过」。
- 任务成功退出后，整体进度才显示 100%。进程尚未退出时最多显示 99%。
- 失败、取消会保留最后进度并显示对应状态，不会自动补成 100%。
- 汇总、Promotion 等独立操作只显示实际可获取的阶段信息；无法获取处理总量时，当前阶段使用等待动画。

## 实现与限制

工作进程通过带 `@@INTENT_PROGRESS@@` 前缀的 JSON 事件上报计划、阶段切换、计数和跳过。Web 服务启动的子进程自动设置 `INTENT_PROGRESS=1`；普通 CLI 默认不输出事件。事件与普通日志分开处理，支持 UTF-8 分块解码以及 tqdm 的回车刷新。

任务详情接口 `/api/jobs/{job_id}` 返回 `progress`、`elapsed_seconds` 和增量日志。前端约每 900ms 获取一次，计数上报会节流到约每 250ms；阶段边界和最终条数会立即上报。

任务、进度、Token 统计与日志保存在 data/job_history/，服务重启后恢复历史任务。删除流程时同步清理关联的已结束任务历史与请求记录；运行任务页也可单独删除已结束任务的记录，保留其流程产物。运行中及尚未完成收尾的任务不能删除历史。 任务状态及流程 JSON 使用独立临时文件，写入并关闭后原子替换正式文件；替换遇到拒绝访问或 Windows 文件共享锁时，最多尝试 6 次，额外等待合计约 1.15 秒。持续权限错误仍会报错，原正式文件保留；磁盘已满等其他错误不重试。重启前处于排队或运行状态的任务标记为跟踪中断，不会自动续跑。分类检查点及请求记录独立保存在磁盘，未保存的历史请求无法补回。

## 阶段分层展示

运行任务页面将阶段分为「主流程」和「候选体系迭代」两组，迭代内部通过轮次选择器查看一轮的子阶段，验证和指标保存放在「迭代收尾」。不会将所有轮次的全部阶段平铺。

默认自动跟随当前轮：进入迭代时展开当前轮，跨轮自动切换；进入导出时展开主流程。手动选择历史/未来轮次或点击阶段查看 Token 后暂停跟随，轮询不会打断查看；点击「返回当前阶段」恢复跟随。手动展开/折叠状态在同一任务的刷新间保留，切换任务时重置并定位其当前阶段。已结束任务默认定位最终阶段，展开迭代时选择最后实际执行的轮次，跳过的未来轮次只在下拉列表中显示「未执行」。

每个子阶段依然可以点击查看独立请求次数与 Token，原有统计口径和阶段 ID 不变。

轮次选择器处于鼠标悬停或焦点操作期间，轮询暂缓阶段导航重绘，防止重建原生 select 关闭选项列表；主进度和 Token 详情继续更新。离开选择器后应用最新导航状态，导航内容未变化时不替换 DOM。手动选定轮次时保留键盘焦点，切换任务不受旧选择器交互状态阻挡。
