# Prompt 文件管理

默认系统指令已从 Python 代码抽离。当前共 13 个模板（11 个主流程模板与 2 个可选 Skill 路由模板），页面「Prompt 管理」和实际模型请求共用同一套文件解析逻辑。

## 文件位置

| 位置 | 用途 |
|---|---|
| `prompts/catalog.yaml` | 模板的稳定标识、阶段分组和显示名称 |
| `prompts/defaults/<模块>/<模板名>.txt` | 随项目提供的默认正文，纯文本，可直接编辑 |
| `config/prompts/<模块>/<模板名>.txt` | 页面保存的自定义正文；不存在时使用默认文件 |

例如：

- 默认父主题审核：[NODE_PROMPT.txt](../../prompts/defaults/hierarchy_review/NODE_PROMPT.txt)。
- 页面修改后写入 `config/prompts/hierarchy_review/NODE_PROMPT.txt`。
- 代码使用 `prompt_ref("hierarchy_review.NODE_PROMPT")` 引用，标识不因文件内容变化而改变。

模块中的 EXTRACT_PROMPT、NODE_PROMPT 等符号仅是引用，不再存放指令正文。动态输入（原句、样本、子节点摘要、候选叶子等）及响应结构校验仍由代码构造。

## 页面编辑与文件编辑

选择阶段和模板后，页面显示当前生效文件、默认文件及完整正文。保存当前模板只更新对应的自定义文本文件，不再把正文塞进 config.yaml。

可以直接用编辑器修改当前生效文件，再点击页面「重新读取配置」。没有未保存编辑时会显示最新文件；确有未保存草稿时保留草稿，避免覆盖正在编写的内容。

「恢复默认到编辑器」仅填入默认文件内容；点击保存后移除该模板的自定义文件，后续重新读取默认文件。直接编辑默认文件会改变恢复默认时使用的正文；如需恢复项目原版，使用 Git 查看该文件历史。

模板必须非空且不超过 32000 字符。请保留原有 JSON 字段与证据约束，并保持理由、解释和证据在前、结论选项在后的模型输出要求。

## 生效与并发保存

- 每次任务加载配置时，固定该任务全部有效 Prompt 的正文；修改影响随后新启动的任务。
- Prompt 正文纳入现有分类缓存指纹，新任务不会复用不同正文的分类结果。
- 页面修订号覆盖配置文件、目录元数据、默认正文和自定义正文；外部文件修改后，过期页面保存会提示重新加载。
- 页面在运行任务期间仍禁止修改 Prompt；文件写入采用临时文件替换，多模板保存失败时回退已写入内容。
- 序列化顺序不作额外处理；输出字段顺序由模板指令与示例约束模型生成。

## 旧 YAML 自定义内容

已有 `config.yaml` 中的 prompts 映射仍会被读取，以免丢失已保存的自定义指令；同一模板的独立自定义文件优先。

在页面首次保存时，已注册模板的旧 YAML 正文会迁移到对应文本文件，并清理 YAML 中这些条目。恢复默认不会使旧正文重新出现。其他模型设置、注释及未识别的旧条目保持原有内容。

## 新增模板

1. 在默认目录增加 `<模块>/<模板名>.txt`。
2. 在 catalog.yaml 增加 key、group、label；key 使用 `模块名.模板名`。
3. 调用处使用 prompt_ref(key)，再交给 LocalLLM.chat_json。

新登记模板会出现在页面，无需再维护 Python 目录映射或通过正文相等来识别模板。

## 审查实际请求

“运行任务”的阶段详情与“分类与迭代”的用例共用请求查看组件，默认不展示输入输出。后者可点击“审查流程 LLM 请求”查看整批记录，或点击用例下的“审查相关 LLM 请求”打开弹窗。弹窗支持分页、刷新、展开原始输入、模型输出和解析结果。

用例关联按请求 User 内容中的原句、原子文本或意图 ID 精确匹配字符串值。只包含节点摘要的上层审核可能无法关联单条原句，应从流程入口查看。重复文本可能匹配多个用例的请求。

新运行的页面任务会将记录同时保存到 `data/request_traces/<job_id>/requests.jsonl` 和流程目录的 `requests/requests.jsonl`。流程入口读取后者，服务重启后仍可审查；尚未记录流程关联的历史任务不会自动迁移或补回。

### 服务重启后的任务历史

运行任务的元信息、进度和 Token 统计保存到 `data/job_history/<job_id>/state.json`，日志追加到同目录 `logs.jsonl`。服务启动后自动恢复“最近任务”列表，可继续从阶段详情读取原有请求记录。状态文件以临时文件原子替换，单条损坏记录不影响其他任务恢复。

重启时仍处于排队或运行状态的任务标记为失败，并注明服务重启后无法继续跟踪，不会自动续跑或重新调用模型。此功能上线前未保存的任务列表无法还原；已有流程及其请求记录仍可从“分类与迭代”审查。

旧维护工具（正式任务整理、候选晋升、人工层级文本导入）及其五个 Prompt 已移除，主流程使用 BERTopic 层级命名与审核。

### 递归审查局部细分请求

请求查看器支持“按父子簇查看”，与“请求列表”切换。树按阶段隔离簇编号，展示父簇、子簇及后续细分分支；每页 10 个根簇，按分支最新请求排序。展开簇后点击“查看本簇请求”，按需加载该簇请求，每页 10 条、最新在前，再展开单次请求查看输入输出。

关系来自实际 User 请求的 `cluster_id` 和 `parent_cluster_id`，不通过文本猜测。LLM 完整分组请求现包含这些编号及细分轮次；子簇审核沿用现有编号。历史请求缺少明确编号时保留在列表中；缺少父簇请求时，父节点仅作为结构上下文展示，不代表已发生模型调用。
