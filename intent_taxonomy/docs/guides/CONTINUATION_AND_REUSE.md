# 继续迭代、失败续跑与结果复用

本文对应当前代码，说明选哪个入口、哪些请求可省略，以及新版本会保留什么。各阶段的完整模型输入输出仍见 [WORKFLOW_EXAMPLE.md](WORKFLOW_EXAMPLE.md)。以下命令中的运行编号、任务编号与文件路径是示例，需替换为已有文件。

## 先区分操作

| 目的 | 操作 | 已有轮次 | 原始拆分 | 产物 |
|---|---|---|---|---|
| 用现有结果再迭代几轮 | 继续迭代，选择可用快照 | 新运行从第 1 轮计数 | 复用 | 新派生版本 |
| 恢复失败或取消的任务 | 运行任务中的续跑 | 有有效快照时恢复已完成轮次，重试出错轮次 | 优先使用快照 | 新任务及派生版本 |
| 在已有体系上追加语料 | 继续迭代中的追加新用例入口 | 按新运行规则计数 | 只提取新增原句 | 新旧原句一起导出；入口限制见下文 |
| 只重新导出 | 阶段处理选择 export | 不执行迭代 | 复用 | 新导出版本 |

这些操作不会修改基准版本。只重新导出不会补做审核、解决歧义或生成缺失的父主题。

## 普通继续迭代

页面选择“继续迭代”、基准版本、最大轮数和分类范围。默认 `unresolved_only` 处理噪声、普通待确认簇、尚未解决的匹配冲突及失效归属；有效已审核成员关系可直接继承。`all` 会重新匹配全部有效意图，但语义字段齐全时仍不重复解析对象和动作。

```bash
.venv/bin/python main.py discover --source data/reports/example_run/process/discovery.json --stage iterate --iteration-rounds 3 --iteration-scope unresolved_only
```

这里的 3 表示新运行最多 3 轮，不是从历史第 3 轮继续。每条分类记录保留实际来源：模型匹配、已审核簇成员关系或有效历史归属。继承关系不生成虚假的模型匹配置信度。

## 失败或取消后的续跑

页面只允许复制续跑已结束的失败或取消任务；正在运行的任务不适用。有已保存的流程状态时，后端优先使用 `process/discovery.json` 恢复迭代，不重新从上传文件开始。快照必须通过阶段输入校验，否则返回错误，需选择可用中间结果进行阶段处理。

CLI 可显式恢复：

```bash
.venv/bin/python main.py discover --source data/reports/example_run/process/discovery.json --stage iterate --iteration-rounds 3 --resume-state --resume-trace data/request_traces/example_job/requests.jsonl
```

- `--resume-state` 恢复保存的轮次与归属；有效已完成轮次跳过，尾部带 `processing_errors` 的轮次会重试。
- `--iteration-rounds 3` 在恢复模式下是总轮数上限。例如已完成 2 轮，恢复后从第 3 轮开始，最多执行到第 3 轮；不是额外再执行 3 轮。
- `--resume-trace` 单独控制成功请求回放，不负责恢复轮次。它只读取显式指定任务日志中的成功对话响应，实际请求参数一致且响应仍通过当前模型结构校验时才复用。
- 失败请求、缺少有效解析结果的响应不会回放。Embedding 不从这份对话日志回放，继续使用自己的向量缓存。
- 没有请求日志也可恢复状态，但未被其他缓存覆盖的请求会实际发送。回放命中不会新增模型服务请求或 Token。

若有效已完成轮次已达到上限，不会再执行新的迭代轮次；准备检查与最终验证仍按实际条件处理，因此不能承诺整次任务零请求。

## 追加新用例的数据变化

后端处理追加数据时，保留旧行与旧原子意图。新增行号从旧 `row_id` 最大值后延续，新增原句记录 `source_file`、`source_row`，流程记录 `append_input` 的文件、工作表、文本列与行数。追加前按去除首尾空白后的原句精确去重，剔除与已有原句及本次文件重复的用例，跳过空白行。保留旧记录，不修改历史原句；新增行仍记录其在新文件中的原始数据行号。append_input 同时记录输入、新增、已有重复、文件内重复及空白数量。

新增原句完成提取后，与旧有效意图一起进入增量匹配。默认模式复用有效旧归属，新增和未确认意图参加匹配、发现与审核；结果导出包含新旧全部原句。修改文本列、选择工作表的基础规则见 [INPUT_FILES.md](INPUT_FILES.md)。

**当前入口限制（2026-11-04 核对）：** 页面已提供追加入口，核心流程也实现了追加，但页面构造的命令同时带 `--source` 和 `--input`，当前 CLI 将二者设为互斥，实际执行会被参数解析器拒绝。另外，页面追加工作表时传 `--sheet-name`，CLI 接受的是 `--sheet`。这些是已核对的实现缺口，不能按完整可用功能操作；本文不提供同时传这两个互斥参数的命令。参数冲突修复后才可通过该入口完成追加。

## 七种复用分别省掉什么

| 复用 | 成立条件与失效原因 | 命中后省掉的工作 | 查看位置 |
|---|---|---|---|
| 已完成轮次恢复 | 显式恢复有效快照；错误轮次重试 | 已完成轮次的重复执行 | `iteration.rounds` |
| 成功请求回放 | 显式选择日志，完整请求身份匹配，当前响应结构仍有效 | 对应对话模型请求 | 请求记录的 `replayed` |
| 原子文本和主题向量 | 文本与向量服务配置身份匹配 | 对应 Embedding 请求 | 向量缓存及实际 Embedding 用量 |
| 意图归属继承 | 任务存在且叶子批准，定义有效，未解决冲突不得强行继承 | 对应意图的候选判断和消歧 | 轮次 classified/reused 数及 assignment 来源 |
| 簇一致性审核复用 | 完整成员、实际样本、审核 Prompt、模型配置相同且旧审核有效 | 对应簇审核请求 | `review_reuse`、`review_source` |
| 叶子命名复用 | 成员、命名样本、有效审核及配置指纹相同，旧名称已批准且未被修改 | 对应叶子命名请求 | `reused_nodes`、`naming_source` |
| 叶子归并缓存 | 已完成整轮身份相同，或某个候选对身份相同 | 整轮检查，或对应候选对的提案/验证请求 | `leaf_merging.passes` 与 `cache` |

单文本簇的本地语义检查是“没有可比较的多条不同文本”，不等同于复用了一次过去的模型审核。它也不自动保证命名通过；语义准入与支持等级分别记录。

## 整轮归并跳过与候选对缓存

整轮跳过在候选向量计算之前判断。只有已经处理完、没有错误或延后候选，且体系、成员、冲突、Prompt、模型、Embedding 和候选策略身份未变化时，才记录 `skip_reason=unchanged_completed_pass`，直接复用完成状态。

未命中整轮完成状态时，才继续生成候选并检查逐对缓存。候选对缓存命中可省提案和验证，但可能仍需要计算候选向量；不要把这两种命中混为一谈。

有真实合并时旧完成身份会失效，后续需检查新候选。共享叶子导致的延后、预算不足及错误均不能标为已完成；还有待处理候选时不能宣称已收敛。归并的完整请求格式见 [流程示例第 9.6 节](WORKFLOW_EXAMPLE.md#96-叶子实例泛化与归并完整输入与输出)。

## 怎样核对有没有真的省请求

先看新任务各阶段实际 LLM / Embedding 请求与服务端用量，再看迭代中的 classified/reused 数、簇审核复用数、节点命名复用数和归并完成状态。条目数、意图数、叶子数都不直接等于请求数；同层并发只影响耗时。

缓存命中、状态恢复以及手工导出不应被当作新服务调用。历史服务用量仍属于原任务；新派生版本只统计这次实际产生的请求。若仍然出现模型调用，先按对应复用的失效条件检查输入、Prompt 或模型设置是否变化，而不是只比较任务版本号。

### 过期相邻簇引用

迭代重建簇列表后会清理旧的 `neighbor_pairs` 与 `pair_reviews`；后续细分可生成新的邻居候选。读取已有结果继续迭代时，若邻居候选引用已删除簇，会清理整份旧候选关系及对应审核记录，并通过 `input_repairs` 记录原因。原始文件保持不变。真实成员、主题树和叶子映射仍严格验证。单独执行跨簇边界复核时，失效候选仍会被拒绝，需先重建邻居关系。


追加用例与主流程复用同一套文件导入状态、工作表/文本列选择和样例预览逻辑。Excel 先选择工作表再显示文本列，CSV 直接选择文本列；选择有效文本列且文件读取完成后才允许带追加输入提交。切换文件取消旧请求，清除追加文件同时清空隐藏路径、预览及选择状态。
